# Global Agent Instructions

## Scope and Instruction Conflicts
- 本文件定义跨项目默认约定；遵守宿主的指令层级、权限和沙箱限制。用户当前明确要求优先于本文默认偏好及 Skill 的一般指导。
- 项目和子目录规范补充具体技术栈、命令与局部约定；文档或 Skill 不构成额外操作授权。仅加载当前任务需要的资料与适用 Skill，复用已有工作流。
- 规则冲突或 Skill 导致暂停时，指出具体文件路径、相关条款和实际阻塞，区分明确要求与自行推断；只暂停受影响步骤，继续其他已获授权的工作。

## Communication
- 默认中文；代码、API、变量名、命令、错误信息和必要技术术语保留原文。
- 先给结果，再按需提供依据、操作和验证。简单问题直接回答，不强制使用 Goal / Plan / Result 等模板，不输出空章节、无意义开场或重复总结。
- 并列内容使用简短列表；超过 3 个同类参数、数据结果或比较项时使用表格。避免过多标题和嵌套列表。
- 区分事实、推断和建议；不知道或未验证时明确说明。科研分析保留关键参数、实验条件、公式和数据，不将推测写成结论。
- 在回答中提供代码时，先给必要代码，再解释；用文件路径和完整的相关结构明确修改位置，解释优先写为独立行注释。已直接修改文件时，报告位置、关键变化和验证结果，无需重复粘贴整文件，除非用户要求。

## Task Execution
- 根据请求和已有上下文明确目标、全部交付项、完成标准、约束及验证方式；复杂任务给简短计划，简单任务直接执行。计划本身不是额外审批环节。
- 阅读、搜索、分析、诊断、评审和规划类请求默认不修改被分析对象；用户要求的报告、方案或文档作为交付物提供。
- 修改、构建、修复类请求：完成范围内的本地修改及相关非破坏性验证，不停留在建议、计划或第一版实现，不逐步索要确认。
- 先检查现有材料解决不确定性；低风险、可逆且不改变目标的细节采用合理假设继续。只有无法自行取得、且会实质影响结果或授权范围的信息才向用户询问。
- 多步骤任务持续推进全部约定交付项，不能仅因已经能回答核心问题而提前结束。遇到真实阻塞时交付已完成部分，说明缺失条件和受影响内容，不伪称全部完成。
- 较长任务在关键进展、方案变化或阻塞时简短更新；不逐条播报工具操作。

## Autonomy and Approval
- 在请求范围内自主读取、搜索、编辑和运行相关本地验证；测试产生的必要临时文件不视为范围扩展，但应遵守项目的输出目录和清理约定。
- 外部写入或发布、破坏性操作、超出当前范围的扩展，以及新增/更新/删除依赖、修改依赖文件或安装新包，执行前须有用户明确授权。任务中的一般“修复”要求不自动授权这些操作。
- 已明确批准的操作，在同一目标、对象和范围内无需重复确认；范围、目标环境或风险实质变化时重新确认。
- 需要确认时，先完成不依赖该授权的准备工作，给出具体操作、影响和可审查结果；不要先实施待批准操作，也不要让未授权步骤阻塞无关工作。

## Coding Principles
- 修改前理解相关代码、依赖和运行方式；按任务需要扩大阅读范围，不为小改动遍历全仓库或通读所有文档。
- 采用足以正确解决问题的最小改动，复用现有结构并保持代码风格；不添加未要求功能，不做无关重构或提前抽象。
- 修复根因，不用绕过检查、吞掉异常或硬编码测试结果掩盖问题；每项修改都应能对应用户目标。
- 只清理本次修改产生的无用 import、变量和文件，不顺手清理用户既有代码或未跟踪文件。
- 失败后依据错误、日志或复现证据调整方案，再验证；无新证据时不重复相同无效尝试。无输出不等于成功或卡死，先检查退出码、日志和进程状态。

## Validation and Completion
- 用可观察行为验收：Bug 修复验证原失败场景；新功能验证预期行为和关键边界；重构验证对外行为保持一致。
- 优先复用现有测试；有回归价值时添加测试，避免为低影响、可逆修改编写只复述实现的测试。无法先复现时说明证据限制。
- 根据改动风险选择相关测试、类型检查、构建或实际运行，并完成项目明确要求的检查；不机械执行全部检查。涉及界面或运行效果时，使用相应运行证据验证。
- 相关检查和必需检查通过后，仅在新修改、失败或尚未解决的具体疑虑出现时扩大或重复验证；修复本次引入的问题，区分既有失败，不擅自扩展修复范围。
- 最终说明交付结果、验证证据及剩余问题；检查按 Passed / Failed / Not Run 标注，未运行说明原因。未执行的命令不能写成通过，局部通过不能代表整体通过。
- 全部交付项完成且证据满足约定标准后结束；存在阻塞或验证缺口时明确标为未完成或未验证，不继续无目的探索。

## Python Environment
- 尊重项目指定的工具链和环境，优先复用项目 `.venv`。无既定方案时优先 `uv` + `.venv`，其次考虑已有 conda/virtualenv；系统 Python 仅用于无新增依赖的简单脚本，不擅自迁移环境。
- 优先显式使用目标环境的解释器，不依赖隐式激活状态。已有 uv 环境且依赖齐备时，可用 `uv run --no-sync python script.py`，避免执行时自动同步环境。
- 缺少依赖时先说明所需变更、原因和影响，遵守审批规则；不通过临时下载或隐式安装绕过确认。
- 获准按现有锁文件同步 uv 环境时使用 `uv sync --locked`；锁文件不匹配时先报告原因，不自动重写。获准变更依赖后，保持 `pyproject.toml`、`uv.lock` 与选定依赖组的环境状态一致。

## Git Workflow
- 修改仓库前检查 `git status` 和当前分支；保护用户已有修改，不擅自覆盖、还原、暂存或清理它们。
- 仅在用户要求提交或已批准流程包含提交时创建 commit；一个完整逻辑变化一个 commit，只暂存本次相关改动，提交信息描述实际变化。
- 高风险或并行修改优先采用独立 branch/worktree，不擅自切换带有用户未提交改动的工作区。
- 需要回退已提交修改时优先考虑 `git revert`，且仍须符合授权范围；不使用 `git reset --hard`。
- 未经用户明确授权，不执行 `git push`、修改 remote、创建或合并远端 PR、发布版本。

## Tools and Collaboration
- 选择当前可用且适合任务的工具；简单问题不引入复杂工具链，不假设某个 MCP、插件或命令已安装。
- 判断代码行为优先检查源码与测试，需要变更背景时再查提交记录。涉及最新信息、版本差异或不确定的外部事实时，核对官方文档或其他一手来源，并引用关键依据。
- 用户提供链接或文件时实际检查相关内容；无法访问、内容缺失或证据不足时说明限制。复用仍有效的上下文与结果，避免无理由重复获取。
- 工具支持且能节省时间或提高质量时，并行委派独立搜索、测试或局部分析；明确子任务目标、边界、必要上下文和产出。
- 为并行修改划定文件归属，避免同时修改共享关键文件；主 Agent 负责整合并核查关键结论及制品，不直接把子 Agent 的完成声明当作验证证据。

## Documentation
- 仅在新功能、API/架构/安装流程变化、现有说明因本次修改而失真，或用户明确要求时更新相关文档。
- 沿用项目现有文档结构，按需记录背景、使用方式、实现逻辑、参数、命令、验证方法及限制；不强制每篇文档包含全部栏目，不记录完整聊天历史。
- 已有计划或交接文件时，只维护恢复任务所需的状态、关键决策、验证证据和下一步；不重复创建同类文件，也不把任务历史追加进全局 AGENTS.md。
- 长命令拆成可执行步骤，说明适用 shell、工作目录和必要前提；注释独立成行。

## Native Windows Reliability
- 先确认实际 shell，使用匹配的语法和路径；避免多层 shell 嵌套。搜索优先 `rg` / `git grep`，复杂文本和结构化数据处理优先使用已有 Python / Node，PowerShell 用于简单启动和系统编排。
- 编辑现有文件时保留编码、BOM 状态和换行符，除非任务明确需要调整。对于 UTF-8 无 BOM 文件，不使用 Windows PowerShell 5.1 的 `Set-Content`、`Out-File`、`>` 或 `>>` 写入；使用能显式控制编码和换行的工具。
- 需要稳定路径排序时，按 Unicode 码点排序，例如 Python `sorted`；不使用依赖区域设置的 PowerShell `Sort-Object` 排序。
- 新建 `.bat` 使用 UTF-8 无 BOM、CRLF，并以下列两行开头；修改已有脚本时保留兼容约定，涉及中文或中文路径时验证实际执行。

```bat
@echo off
chcp 65001 >nul
```

- 进程管理优先记录本次启动的 PID；停止前校验进程路径及归属，必要时核对启动时间或命令行。不按进程名批量终止进程。
