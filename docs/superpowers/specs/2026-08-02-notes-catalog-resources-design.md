# 笔记目录、README 清单与资源页设计

## 目标

将分散在仓库根目录的笔记统一迁移到 `notes/`，并把根目录 `README.md` 设计为同时服务两类读者的唯一公开清单：GitHub 访问者可直接浏览完整目录，网站构建也从同一目录生成指南和资源页面。

迁移必须保持现有 `/guides/...` URL、Markdown 内部链接、图片引用和 GitHub Pages 发布流程不变。根目录 `20260614.md` 删除。

## 仓库结构

以下目录整体移动，目录内部的 Markdown、图片和配套文件一起保留：

```text
notes/
├── agents/
├── models/
├── operating-system/
├── others/
└── programme-env/
```

`README.md`、`AGENTS.md`、网站源码、项目文档、构建配置和 `public/` 继续保留在根目录。`docs/` 是项目设计记录，不并入笔记目录。

## README 双用途格式

README 保留项目介绍、网站入口和使用说明。网站只解析两个隐藏标记之间的目录内容，避免把徽章、项目地址或维护说明误认为公开资源：

```markdown
<!-- site-catalog:start -->

## 1. 基础环境

### 指南

- [Git 指南](notes/others/git.md) — Git 与 GitHub 基础配置
- [Node.js 指南](notes/programme-env/nodejs.md) — Node.js 安装与验证

### 配套资源

- [cc.bat](notes/agents/claude-code/cc.bat) — Claude Code Windows 快捷启动脚本
- [GitHub 官方文档](https://docs.github.com/) — GitHub 使用参考

<!-- site-catalog:end -->
```

格式约定：

- `##` 是网站一级分类，按 README 出现顺序展示。
- `###` 是分类内分组；没有三级标题时使用所属二级分类作为分组。
- 公开条目使用列表链接：`- [标题](目标) — 可选简介`。
- 链接前的 emoji 仅改善 GitHub 可读性，不决定网站类型。
- 标记外的 Markdown 可自由编辑，不参与网站清单解析。
- README 中未列出的笔记和文件不会公开。

现有 README 内容按“基础环境、系统与运行环境、智能体、智能体扩展、科研助力、模型选型、AI 新闻、补充资料”整理。当前所有有效本地链接和外部链接保留，但路径更新为 `notes/...`；旧的 `psiQAQ/agent-lab-notes` 绝对链接更新为 `psiQAQ/psiQAQ.github.io`。

README 文末增加简短维护说明，给出新增指南、外部链接和本地文件的三个模板，以及 `commit`、`push main` 后自动发布的流程。

## 清单数据模型

构建时读取 README 目录，记录每个链接的分类、分组、标签、目标和可选简介，然后按目标类型处理。

### 本地 Markdown

- 目标必须位于 `notes/` 且文件存在。
- Markdown 必须包含一级标题。
- 物理路径中的 `notes/` 不进入公开 slug，因此 `notes/others/zotero.md` 仍生成 `/guides/others/zotero`。
- 分类和顺序来自 README，不再由源码中的目录判断硬编码。

### 外部链接

- `http://` 和 `https://` 链接进入 `/resources`。
- 使用 README 标签作为标题，可选简介作为说明。
- 新标签页打开，并设置安全的 `rel` 属性。
- 构建不访问第三方网站，避免外部网络故障阻塞发布。

### 本地文本源码

- README 普通链接指向的可展示文本文件进入 `/resources`。
- 当前仓库的 `.bat`、`.sh`、`.py` 纳入文本源码；实现可同时支持常用脚本和配置文本扩展名。
- 页面标题固定使用文件名，不使用 README 标签覆盖。
- 页面显示转义后的完整源码、语言标签和复制按钮；复制成功或失败提供可访问状态提示。
- 只有 README 列出的文件公开，未列出的脚本不进入构建产物。

### 图片与不可展示文件

- Markdown 图片语法 `![说明](路径)` 仅用于指南配图，不进入资源清单。
- README 中通过普通链接列出的图片、压缩包、文档或其他非文本文件进入 `/resources`，提供下载链接，不尝试内嵌为源码。
- 下载链接使用构建产物 URL，并保留原文件名作为下载名称。
- 本地目标不存在时构建失败；扩展名不属于文本源码集合时按下载资源处理。

## 网站页面

### 知识库

`/library` 只展示本地 Markdown 指南，分类、分组和顺序由 README 决定。现有全文搜索继续只搜索指南正文。

### 资源页

新增 `/resources` 并加入全局导航。页面按 README 分类展示：

- 外部资源卡片；
- 可复制的本地源码；
- 不可展示文件的下载条目。

资源页不复制 Markdown 指南内容，避免与知识库重复。

### 其他页面

首页、新手路径、指南侧栏和既有路由保持现有行为。首页的公开指南数量仍只统计 Markdown；资源页独立显示资源数量。

## 引用与迁移规则

- 五个笔记目录整体移动，保留内部相对层级，因此笔记之间的相对链接和图片路径无需重写。
- 根目录 README 的本地目标统一增加 `notes/` 前缀。
- 内容加载器对物理路径去除 `notes/` 前缀后再生成 slug 和解析相对引用。
- 网站源码、测试和项目文档中描述真实物理位置的路径同步更新；表示公开 URL 的 `/guides/...` 不修改。

## 错误处理

构建必须对以下情况给出明确错误并停止：

- README 缺少目录开始或结束标记；
- 目录中的本地链接目标不存在或逃逸 `notes/`；
- 公开 Markdown 没有一级标题；
- 不同 Markdown 生成重复 slug；
- 指南引用的图片缺失。

第三方 URL 不进行在线可用性检查。本地文件不属于可展示文本类型时自动作为下载资源，不因格式未知而失败。

## 验证标准

自动验证覆盖：

- 根目录不再存在五个旧笔记目录和 `20260614.md`；
- `notes/` 保留全部原笔记、图片和配套文件；
- README 目录中的所有本地链接存在；
- README 分类顺序同时反映在知识库和资源页；
- 原有 `/guides/...` 路由、中文路径、全文搜索和图片渲染继续工作；
- `/resources` 能展示外部链接、以文件名为标题的可复制源码，以及下载资源；
- Markdown 图片不会被误收录为资源；
- 静态导出、完整测试、lint 和 `git diff --check` 通过。

首次部署后验证首页、知识库、资源页、一篇中文指南和至少一个源码资源。远端 push 与公开部署仍在本地验证完成后执行。

## 后续维护流程

新增指南：

```text
添加 notes/.../new-note.md
→ 在 README 目录中添加本地 Markdown 链接
→ commit
→ push main
```

新增外部资源、本地源码或下载文件时使用同一流程，只需改变 README 链接目标。GitHub Actions 在 `main` 更新后自动构建并发布网站。
