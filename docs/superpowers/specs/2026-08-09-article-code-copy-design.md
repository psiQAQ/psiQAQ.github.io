# 文章代码块复制按钮设计

## 目标与范围

为所有通过 `renderMarkdown` 展示的文章代码块增加复制按钮，覆盖：

- `/guides/*` 知识库文章；
- `/resources/*` 中以文章形式展示的 Markdown 学习资源。

纯源码资源页继续使用现有“复制源码”按钮，不改变其结构或行为。

## 交互与样式

每个块级 `<pre><code>` 使用统一容器，按钮固定在容器内部右上角。代码块保持现有深色背景；按钮使用浅色背景和深色文字，形成反色对比。按钮不得遮挡代码，代码仍可横向滚动。

按钮初始文字为“点我复制~”。点击后只复制 `<code>` 的纯文本，不包含按钮文字或额外标记。复制成功后显示“已复制！”，3 秒后恢复“点我复制~”；3 秒内再次成功复制时重新开始计时。复制失败时显示“复制失败”，不显示成功状态。

按钮使用原生 `<button type="button">`，提供“复制代码”的无障碍名称，状态文字通过礼貌播报区域通知辅助技术。

## 实现结构

在共享的 Markdown renderer 中包装默认代码块输出并加入按钮标记，保留 Marked 现有的代码转义、换行和语言 class。

根布局挂载一个轻量客户端控制器，通过事件委托处理所有代码块按钮。控制器从按钮所属容器读取 `<code>.textContent`，调用 `navigator.clipboard.writeText`，并管理每个按钮的 3 秒恢复计时。该方案避免两个文章页面重复实现，也不新增依赖。

## 验证标准

自动验证覆盖：

- 知识库文章和 Markdown 资源页输出代码块按钮；
- 代码内容仍正确转义并保留语言 class；
- 点击复制的文本仅为代码内容；
- 成功状态为“已复制！”，恢复延迟为 3000ms；
- 重复点击会重置恢复计时；
- `npm test`、`npm run lint`、静态导出和 `git diff --check` 通过。

实现完成并验证后直接推送 `main`，等待 GitHub Pages 部署成功并检查线上资源。
